Les 60 worktrees d'agents

Libère 51G

Ce que j'ai mesuré

Chaque agent lancé en parallèle a reçu une copie complète du dépôt. Il en reste 60, qui pèsent 51G — c'est-à-dire la quasi-totalité des 58G du dossier. Le travail, lui, est ailleurs : sur les 75 branches, 66 sont déjà fusionnées dans main.

Ce que j'ai vérifié avant de proposer

Les 8 branches non fusionnées ont été dépouillées fichier par fichier. Elles touchent en tout 38 fichiers qui n'existent pas dans main : 36 images — vérifiées une à une, aucune n'est appelée par le module auquel elle appartient (ce sont des générations abandonnées, refaites depuis) — et 2 documents de planification (docs/plan-module-n3-horaire.md, docs/plan-module-n5-saisons.md). Par ailleurs 18 worktrees portent des fichiers jamais commités (46 fichiers neufs, dont 46 existent déjà dans main : PowerPoints, fiches, scripts audio produits ensuite par le chemin normal).

Ce que je propose

Récupérer les 2 documents de planification dans docs/, puis retirer les 60 worktrees et les branches qui vont avec.

Le risque

faibleCe qui disparaît est du travail déjà repris dans main ou des images que plus rien n'appelle. À faire quand aucune session n'est en cours dans le dépôt — un worktree retiré sous les pieds d'un agent le casse.

Les gestes

# 1. récupérer ce qui n'existe nulle part ailleurs
git show <branche>:docs/plan-module-n3-horaire.md > docs/plan-module-n3-horaire.md
git show <branche>:docs/plan-module-n5-saisons.md > docs/plan-module-n5-saisons.md
# 2. retirer les worktrees, puis leurs branches
git worktree list | grep .claude/worktrees | awk '{print $1}' | xargs -n1 git worktree remove --force
git worktree prune
git branch -D $(git branch | grep worktree-agent)

Ce que je propose

# puis la ligne de chemin dans chacun des lecteurs, et :
python3 build/audio_manquant.py    # doit rester à zéro
